# 새 기능 추가 가이드

이 저장소에 기능을 더할 때 따르는 순서와 확인 목록입니다. 사람과 AI 에이전트(`.claude/agents/feature-dev.md`)가 같은 문서를 따릅니다.
구조는 [`ARCHITECTURE.md`](../../ARCHITECTURE.md), 코드 규칙은 [`CLAUDE.md`](../../CLAUDE.md) 를 기준으로 합니다.

예시로 "책 리뷰 목록 보기"(상세 화면에서 리뷰 화면으로 이동, 서버 API 로 리뷰를 받음)를 듭니다.

---

## 0. 시작 전에 정할 것

| 질문 | 정하는 것 | 예시 |
|---|---|---|
| 사용자가 무엇을 하나? | UseCase 이름과 입력 | `GetReviewsUseCase(bookId, page)` |
| 데이터는 어디서 오나? | data 모듈 종류 | 서버 → `:data:api:<API 경로>` / 기기만 → `:data:local:<대상>` |
| 어느 주제인가? | domain 모듈 | 새 주제 → `:domain:review` / 기존 주제 → 그 모듈에 더함 |
| 화면은 무엇인가? | 기능 main 모듈 | `:presentation:feature:review:main` |
| 다른 화면이 여기로 오나? | Router 가 필요한지 | 상세에서 오므로 `ReviewRouter` 필요 |
| 오프라인일 때는? | 캐시를 둘지, 오류만 보일지 | 기획 단계에서 정하고 decision-log 에 남긴다 |

만들 파일 목록을 먼저 적고 확인받은 뒤 시작합니다(작업은 단계별로).

## 1. domain — 행동부터 정의한다

```
domain/review/src/main/kotlin/domain/review/
├─ data/ReviewDTO.kt
├─ repo/IReviewRepository.kt        fun getReviews(...): DomainResult<...>
└─ usecase/GetReviewsUseCase.kt     operator fun invoke(...) = repository.getReviews(...)
```

- [ ] `build.gradle.kts` 에 `id("convention.domain")` 한 줄. 다른 domain 주제 모듈을 의존하지 않는다
- [ ] `settings.gradle.kts` 의 `include` 에 더한다
- [ ] 저장소 함수는 `DomainResult`(관찰은 `Flow<DomainResult<T>>`)를 돌려준다
- [ ] UseCase 는 행동 하나에 하나, `operator fun invoke`, 저장소 함수 하나만 부른다. 판단 로직을 넣지 않는다
- [ ] DTO 는 `~DTO`, enum 은 접미사 없이

## 2. data — 출처별로 구현한다

```
data/api/review/src/main/java/data/api/review/
├─ service/IReviewService.kt          Retrofit 인터페이스
├─ data/ReviewApi.kt                  응답 모양(필드 모두 nullable, 기본값 없음) + toDTO 변환
├─ source/remote/IReviewRemoteDataSource.kt · ReviewRemoteDataSourceImpl.kt   safeApiCall { service.get(...) }
├─ repo/ReviewRepositoryImpl.kt        원본 → DTO, (필요하면) 캐시 대체
└─ di/IReviewModule.kt · ReviewServiceModule.kt
```

- [ ] `build.gradle.kts` 에 `id("convention.data")` 와 쓰는 domain 모듈. API 모듈은 Retrofit(`libs.retrofit`), kotlinx.serialization 플러그인(`alias(libs.plugins.kotlin.serialization)`)과 `libs.kotlinx.serialization.json` 도 직접 적는다(`convention.data` 는 붙이지 않는다)
- [ ] 데이터 소스는 원본(`~Api` · `~Entity`)만 주고받는다. DTO 변환은 저장소에서
- [ ] 서버 호출은 `safeApiCall {}`, DB 호출은 `safeDbCall {}` · `safeDbFlow()`. try-catch 를 직접 쓰지 않는다
- [ ] 바인딩은 이 모듈의 `di/` 에, `@InstallIn(ViewModelComponent::class)` + `@ViewModelScoped`
- [ ] 새 테이블이면 `:data:base` 의 `db/` 에 Entity · DAO 를 더하고 `AbsBookDatabase` 에 등록한다
- [ ] API 는 문서가 아니라 실제 호출로 응답을 확인하고 `docs/api.md` 에 남긴다(키 값은 적지 않는다)

## 3. presentation — 화면을 만든다

```
presentation/feature/review/main/src/main/java/presentation/feature/review/main/
├─ data/ReviewUiState.kt              UiState + UiStatus(로딩·결과·빈 결과·오류)
├─ vm/ReviewViewModel.kt              UseCase 만 부른다, when 으로 결과 판단
├─ view/ReviewScreen.kt               ReviewScreen(public) + ReviewContent(internal)
├─ view/component/ReviewItemView.kt   <기능>~View, internal, @Preview
├─ mapper/ReviewViewDataMapper.kt     DTO → ViewData
├─ router/ReviewRouterImpl.kt         INavigator 로 이동
└─ di/IReviewNavigationModule.kt      Router 바인딩 + "PageData → 화면" @IntoSet
```

그리고 `:presentation:router` 에 계약을 더합니다.

```kotlin
abstract class ReviewRouter {
    @Serializable
    data class PageData(val bookId: String) : NavKey
    abstract fun open(pageData: PageData)
}
```

- [ ] `build.gradle.kts` 에 `id("convention.presentation")` 와 쓰는 domain 모듈만. 다른 기능 main 모듈을 의존하지 않는다
- [ ] ViewModel 은 `MutableStateFlow<UiState>` 하나, `update {}` 로만 바꾼다
- [ ] `DomainResult` 는 `when` 으로 Success · Fail · Error 를 모두 적는다. 실패 문구는 `result_failure`
- [ ] 화면에서 쓰는 문자열은 그 모듈의 `strings.xml`(한국어)에, 여러 화면이 쓰면 `:presentation:base`
- [ ] 여백은 `Spacing` 토큰만, 공통 UI 는 `:core:designsystem` 에 이미 있는지 먼저 본다
- [ ] 이 화면을 여는 쪽(상세)은 `ReviewRouter` 를 주입받아 `open(...)` 만 부른다

## 4. :app 에 연결한다

- [ ] `app/build.gradle.kts` 에 새 main 모듈과 data 모듈을 더한다(Hilt 그래프)
- [ ] 새 탭이면 `MainScaffold` 의 `Tab` 과 백스택에 더한다. 탭이 아니면 `:app` 코드는 고치지 않는다

## 5. 테스트와 확인

- [ ] 테스트는 조용히 깨지기 쉬운 곳에만: 응답 매퍼(null · 키), 저장소의 대체 순서, 캐시 규칙, DAO 쿼리. ViewModel 은 실행으로 확인한다
- [ ] `./gradlew testDebugUnitTest test` 와 `./gradlew assembleDebug` 통과, 컴파일러 경고 0건
- [ ] 에뮬레이터에서 확인: 정상 · 빈 결과 · 오프라인 · 회전 · 600dp 이상 2칸 · 뒤로 가기

## 다른 경우

**기존 화면에 섹션을 더할 때**(예: 즐겨찾기 탭에 '최근 본 책')
- 새 모듈 없이 기존 주제의 domain · data 모듈에 저장소 함수와 UseCase 를 더할지, 새 주제 모듈로 나눌지 먼저 정한다(주제 모듈끼리는 서로 의존하지 않는다).
- 화면은 기존 ViewModel 에 관찰을 더하고, `UiState` 에 별도 칸을 둔다(`UiStatus` 는 본문 상태 하나만). 섹션은 `<기능>~View` 조각으로 만든다.

**테이블을 더하거나 바꿀 때**
- Entity · DAO 는 `:data:base` 의 `db/` 에 두고 `AbsBookDatabase` 에 등록한다.
- 책을 가리키는 테이블이면 `IBookDao.deleteUnreferenced` 의 조건에 더한다. 빠뜨리면 새 검색 때 그 책 정보가 지워진다.
- 배포 뒤라면 DB 버전을 올리고 마이그레이션을 더한다.
