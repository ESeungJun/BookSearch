# v1 폐기 기록

첫 버전(v1)은 AI 에이전트 두 개로 만들었다. 요구사항 정리 에이전트(plan-haul)가 기획서를 쓰고, 구현 에이전트(dev-haul)가 설계서·ADR·코드를 썼다.
작성자는 결정이 필요한 지점마다 답하고, 앱을 직접 실행해 동작을 점검했다(결정 D-01~D-38).
2026-10-10에 작성자가 구조와 코드를 직접 검토한 뒤 v1 전체를 폐기하고 새로 만들기로 했다(D-39).

v1 저장소는 비공개로 보관한다. 이 저장소에는 v1의 결정 기록(`decision-log.md` 부록)과 이 문서만 남긴다.

## v1 규모

| 항목 | v1 |
|---|---|
| 모듈 | 15개 (`presentation`·`domain`·`data`·`di` 각각 `base` + 도메인, `core:logger`, `build-logic`) |
| Kotlin 파일 | main 119개, test 13개 |
| 코드 | main 약 5,600줄 |
| 문서 | md 34개 (ADR 19건, 기획서 약 500줄, 구현설계서, 가이드, AI 단독 결정 목록 B1~B55) |
| 단위 테스트 | 64건 통과 |

기능은 요구사항을 모두 충족했고 빌드·테스트도 통과했다. 폐기 이유는 동작이 아니라 **구조와 읽기 어려움**이다.

## 폐기 이유 (작성자 검토 결과)

1. **파일과 구조가 너무 많고 복잡하다.** `presentation:base`에 검색창·안내 줄·맨 위로 버튼 같은 공용 컴포넌트가 섞여 있고, `presentation:component`로 잡힌 것은 실제로는 검색 화면에만 쓰는 것이었다.
2. **파일 안의 코드도 복잡해 읽기 어렵다.**
3. **data 계층이 Context를 들고 네트워크 연결 상태를 판단했다.** 데이터 계층의 책임이 아니다.
4. **API 호출의 예외 처리가 과도하다.**
5. **app 모듈은 `navigation` 패키지 하나에 모든 것이 들어 있었다.**
6. **변수 선언의 위치와 순서가 제각각이다.**
7. **UseCase가 대부분 Flow를 돌려주고, 새로고침은 trigger Flow 값을 바꿔서 했다.** `refresh()` 함수를 두고 당겨서 새로고침 때 부르면 충분하다.
8. **`data/book/schemas`(Room 스키마 JSON)의 역할이 불분명하다.** 배포한 적 없는 앱에 마이그레이션 이력 4단계가 쌓였다.
9. **data 모듈에도 패키지와 파일이 너무 많다.**

정리하면, 로직이 서로 얽혀 있어 코드 흐름을 따라가기 어려웠다.

## 원인 분석

구조 하나만의 문제가 아니라 **만드는 방식**의 문제로 봤다.
- 구현 에이전트가 한 번에 많은 코드를 쓰고 작성자가 나중에 검토하는 방식이었다. 그래서 에이전트의 기본 습관이 검토 전에 이미 코드가 됐다. 그 습관은 레이어마다 다시 `base`와 도메인으로 쪼개기, 방어 코드, 문서 다수였다.
- AI가 혼자 정한 세부 결정이 55건까지 쌓였고, 작성자가 모두 검토하기 전에 다음 기능이 올라갔다.

## v2에서 바꾼 것

| v1 | v2 |
|---|---|
| 에이전트가 기능 단위로 자율 구현 | 메인 세션이 단계별로 구현. 단계 전 파일 목록 확인, 단계 후 diff 검토 (D-41) |
| 모듈 15개, 레이어 × (`base` + 도메인) | 모듈 8개: 레이어 우선은 유지하되 레이어당 모듈 하나. `di`는 별도 모듈 유지 (D-40) |
| UseCase 가 Flow 를 돌려주고 trigger 로 새로고침 | UseCase 는 사용자 행동 하나당 하나, `invoke` 한 번 호출로 끝나는 행동 함수. 새로고침은 ViewModel 함수에서 같은 UseCase 를 다시 부른다 (D-44) |
| 연결 상태(Context) 확인 + 3초 타임아웃 | 요청에 3초 타임아웃만 건다. 실패하면 캐시. 연결 상태 확인 없음 |
| Flow + trigger로 새로고침 | `refresh()` 같은 함수 |
| Room 스키마 v1~v4 + 마이그레이션 | 배포 전이라 버전 1, 스키마 내보내기 없음 |
| 직접 만든 로그 인터셉터 | 표준 `HttpLoggingInterceptor` |

## 가져가지 않는 것
- 최근 검색어 기능 전체 (D-24~D-28, D-30, D-34, D-37 → D-38에서 삭제)
- 온보딩 에이전트를 저장소에 포함(D-06): v2에서는 README와 CLAUDE.md로 대신한다. 다시 넣을지는 문서 단계에서 정한다.
- ADR 19건, 기획서, 구현설계서, AI 단독 결정 목록(B1~B55): 근거는 결정 기록 부록에 남아 있다. v2는 새로 정하는 결정만 새로 쓴다.
