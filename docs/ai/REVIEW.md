# AI 단독 결정 — 작성자 리뷰용

AI 가 작성자 확인 없이 정한 것(`추천안 기본 채택`)을 모은다. 단계 리뷰 때 작성자와 함께 보고, 확정·변경되면 `decision-log.md` 1절로 옮긴 뒤 여기에는 결과만 표시한다.

| ID | 단계 | 주제 | 선택지 (**고른 것**) | 이유 | 다르게 하면 | 위치 |
|---|---|---|---|---|---|---|
| R-01 | v1 이월 | 두 ISBN 이 모두 있을 때 매칭 키 | ISBN10 / **ISBN13** | 13자리가 현행 표준이고 실측 110건 모두 ISBN13 을 가짐 | ISBN10 우선이면 13 단독 책과 키 체계가 갈림 | `docs/api.md` |
| ~~R-02~~ | 2단계 | **해소 — D-47(자동 재시도 없음, 다시 시도 버튼)** 5xx·429 자동 재시도 | 없음(버튼만) / **OkHttp 인터셉터에서 GET 2회, 300ms 간격** | 일시 오류를 사용자에게 보이지 않게. HTTP 를 아는 통신 계층에서 끝낸다. **plan-haul 기획서 Q-04 는 '자동 재시도 없음'으로 제안 — 충돌, 작성자 결정 필요** | 없음이면 10% 확률 일시 오류가 곧바로 오류 화면 | `data/api/RetryInterceptor.kt` |
| R-03 | 2단계 | 오프라인 판단 | 연결 상태 관찰 / **요청 실패(3초 초과·IOException)로만** | data 가 Context 를 들지 않는다(v1 지적 3). 느린 연결은 연결 상태로 알 수 없다 | 연결 복귀 시 자동 재요청은 없다 | `BookRepositoryImpl` |
| R-04 | 2단계 | 캐시 LRU 기준 | 마지막 사용 / **마지막 저장 시각** | 저장할 때만 순서를 갱신하면 읽기 경로에 쓰기가 없다 | 캐시로 다시 본 조합도 순서가 오르지 않는다 | `SearchCacheDao.deleteOldCombinations` |
| R-05 | 2단계 | 0건 결과 캐시 | 저장 / **저장 안 함** | 남길 책이 없다 | 오프라인에서 0건 검색어는 '결과 없음' 대신 오류로 보인다 | `BookRepositoryImpl.save` |
| R-06 | 2단계 | 6페이지 이후 책 정보 | 저장 안 함 / **책 정보만 저장, 캐시 목록엔 안 남김** | 상세가 키로 찾을 수 있어야 한다(D-08) | 다음 새 검색 때 정리되므로 그 뒤 프로세스 재시작 시 상세를 못 찾을 수 있다 | `BookRepositoryImpl.save`, `BookDao.deleteUnreferenced` |
| R-07 | 2단계 | 즐겨찾기 검색 범위 | 제목만 / **제목 + 저자** | 원문 '질의어 기반 로컬 검색'에 저자 검색도 자연스럽다 | — | `ObserveFavoritesUseCase` |
| R-08 | 2단계 | 마지막 검색 저장 위치 (D-49) | 별도 테이블·DataStore / **검색 캐시의 가장 최근 저장 행** | 저장할 곳을 하나 더 만들지 않는다 | 0건·실패한 검색은 마지막 검색이 되지 않는다(결과를 받은 검색만) | `SearchCacheDao.getLatest` |
