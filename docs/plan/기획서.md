# BookSearch v2 기획서

기준 문서다. 중심은 「2. 사용자 행동 정의」이며, `:domain:*/usecase` 는 이 표를 코드로 옮긴 것이다.
요구사항 원문은 `docs/requirements/assignment.md`, API 는 `docs/api.md`.
표시 규칙: **(추천)** = AI 가 정한 값·규칙으로 `추천안 기본 채택`(작성자 미확인). **(제안)** = 없는 UseCase 를 새로 제안, 추가 여부는 작성자 결정.

## 1. 요약
- 카카오 도서 검색 API 로 책을 찾고, 즐겨찾기한 책을 로컬에 저장해 보는 안드로이드 앱. 하단 탭 2개(검색 / 즐겨찾기) + 상세.
- 전제 1: 지하철처럼 네트워크가 불안정하다 → 요청은 네트워크 우선, 3초 초과·실패 시 저장된 결과.
- 전제 2: 태블릿·폴더블에서도 쓴다 → 폭 600dp 이상은 목록-상세 2칸.
- 전제 3: 대규모 앱의 한 기능이고 여러 명이 계속 기능을 추가한다 → 레이어 × 기능 모듈, UseCase 목록만 읽어도 할 수 있는 일을 알 수 있게 한다.

## 2. 사용자 행동 정의

| ID | 사용자 행동 | 입력 | 결과 / 규칙 | UseCase |
|---|---|---|---|---|
| U-01 | 검색어를 입력해 책을 찾는다 | 검색어, 정렬(기본 정확도순) | 1페이지(20권)와 총 개수를 받는다. 입력 멈춘 뒤 400ms 후 자동 검색, 최소 1글자(추천). 입력을 비우면 호출 없이 첫 진입 상태로 | `SearchBooksUseCase` |
| U-02 | 검색 정렬을 바꾼다 (정확도순 / 발간일순) | 정렬 | 같은 검색어로 1페이지부터 다시 받고 목록 맨 위부터 보여 준다 | `SearchBooksUseCase` |
| U-03 | 목록 끝까지 내려 다음 페이지를 본다 | 다음 page | 20권씩 이어 붙인다. `isEnd` 면 더 요청하지 않는다 | `SearchBooksUseCase`(page) |
| U-04 | 새로고침하거나 실패 후 다시 시도한다 | 현재 검색어·정렬 | 1페이지부터 다시 호출. 같은 UseCase 를 ViewModel 함수(`refresh`/`retry`)가 다시 부른다 | `SearchBooksUseCase` |
| U-05 | 검색 목록에서 어떤 책이 즐겨찾기인지 본다 | — | 하트 상태를 즐겨찾기에서 계산해 표시. 다른 탭·상세에서 바꾸면 바로 반영 | `ObserveFavoriteKeysUseCase` |
| U-06 | 하트로 즐겨찾기에 넣거나 뺀다 | 책, 현재 상태 | 검색·즐겨찾기·상세 어디서든 같은 행동. 넣을 때 책 정보 전체를 로컬에 저장(오프라인에서도 카드·상세가 성립) | `ToggleFavoriteUseCase` |
| U-07 | 즐겨찾기 목록을 본다 | — | 최근에 넣은 것이 앞. 로컬만 사용, 네트워크 없이 동작 | `ObserveFavoritesUseCase` |
| U-08 | 즐겨찾기를 검색어로 거른다 | 검색어 | 제목·저자에 포함(대소문자 무시)된 책만. 로컬 검색 | `ObserveFavoritesUseCase` |
| U-09 | 즐겨찾기를 제목순으로 정렬한다 | 오름차순 / 내림차순 | 정렬을 바꾸면 맨 위부터. 기본 오름차순(추천). 정렬은 화면이 한다 | — (화면) |
| U-10 | 즐겨찾기를 금액으로 거른다 | 금액 구간 또는 전체 | 판매가(할인가 우선) 기준. 구간: 전체 / 1만 원 미만 / 1~2만 / 2~3만 / 3만 이상(추천). 가격 정보 없는 책은 구간 선택 시 빠진다 | `ObserveFavoritesUseCase` |
| U-11 | 목록의 카드를 눌러 상세를 본다 | 책 key | 상세 API 가 없어 저장해 둔 정보에서 찾는다. 좁은 창은 상세로 이동, 2칸은 오른쪽 칸 갱신. 프로세스 재시작·회전 후에도 key 로 복원 | `GetBookUseCase` |
| U-12 | 상세에서 전체 책 소개를 본다 | 책 `url` | 요약 끝에 "…", '전체 소개 보기'로 도서 페이지를 Custom Tab 으로 연다. 데이터 처리가 없어 UseCase 없음(화면 동작) | — |
| U-13 | 네트워크가 안 될 때 새 검색어로도 저장된 책을 찾는다 | 검색어, 정렬 | 같은 검색어·정렬의 저장 결과가 없으면 기기에 저장된 모든 책(최근 검색 결과·즐겨찾기)에서 제목·저자로 찾아 보여 준다. 다음 페이지 없음, "오프라인이라 저장된 책에서 찾았어요" 안내 | `SearchBooksUseCase` |

- 즐겨찾기 상태(`isFavorite`)는 검색 결과에 저장하지 않고 U-05 에서 계산한다.
- U-01·U-02·U-03·U-04 는 같은 저장소 함수를 페이지만 바꿔 부르므로 `SearchBooksUseCase(query, sort, page)` 하나다.

## 3. 화면 정의

전 화면 공통: 상태는 첫 진입 / 로딩 / 결과 / 빈 결과 / 오류 / 캐시 표시. 오류 문구에는 API 응답 원문(키 일부 포함 가능)을 쓰지 않는다.

### 3-1. 검색 탭 (S1) — U-01~U-06, U-11

| 순서 | 구성 | 내용 |
|---|---|---|
| 1 | 제목·검색창 | "검색", 입력창(placeholder "제목 또는 저자를 입력하세요"(추천)), X 로 비우기 |
| 2 | 안내 줄 | 캐시 표시·오프라인 안내(캐시일 때만). 스크롤하면 접힌다 |
| 3 | 총 개수·정렬 줄 | 왼쪽 "총 N건", 오른쪽 정렬(정확도순/발간일순). 스크롤해도 이 줄만 고정 |
| 4 | 카드 목록 | 카드(아래), 하단 페이징 프로그레스, 맨 위로 버튼, 당겨서 새로고침 |

카드(검색·즐겨찾기 공용): 썸네일 / 제목(줄 수 제한) / 보조 줄 `날짜 - 저자 - 출판사`(저자 2명 초과 시 "외 N명") / 가격(할인가 있으면 할인가 + 정가 취소선, 없으면 "가격 정보 없음") / 하트. 위계: 제목 > 가격 > 보조 줄. 썸네일 없음·로드 실패는 자리표시.

| 상태 | 조건 | 표시 |
|---|---|---|
| 첫 진입 | 검색어 없음 | 아이콘 + "책 제목이나 저자를 검색해 보세요" (검색어 필수라 전체 목록 조회 불가, `api.md`) |
| 로딩 | 첫 검색 중 | 카드 골격 스켈레톤. 새로고침은 전체 프로그레스, 기존 목록 유지 |
| 결과 | 1권 이상 | 카드 목록 |
| 빈 결과 | 0건 | "'검색어' 결과가 없어요" + 다른 검색어 안내 |
| 오류 | 네트워크 실패 + 캐시 없음 | 원인별 문구 + 다시 시도(4절) |
| 캐시 표시 | 3초 초과·실패 + 캐시 있음 | 캐시 결과 + 안내 줄 "저장된 결과 · 마지막 갱신 yyyy-MM-dd HH:mm"(추천) |
| 다음 페이지 실패 | 추가 로드 실패 | 받은 목록 유지 + 목록 끝에 다시 시도 |

### 3-2. 즐겨찾기 탭 (S2) — U-05~U-11

| 순서 | 구성 | 내용 |
|---|---|---|
| 1 | 제목·검색창 | "즐겨찾기", 로컬 검색(placeholder "저장한 책 검색"(추천)) |
| 2 | 총 개수·정렬·필터 줄 | 왼쪽 "m / n권"(거른 수 / 전체), 오른쪽 필터(금액 구간 선택) · 정렬(제목 오름/내림). 고정 |
| 3 | 카드 목록 | S1 과 같은 카드. 맨 위로 버튼. 정렬·필터·검색어가 바뀌면 맨 위부터 |

| 상태 | 조건 | 표시 |
|---|---|---|
| 첫 진입 | 저장된 책 0권 | 하트 아이콘 + "마음에 드는 책에 하트를 눌러 보세요" |
| 로딩 | 로컬 조회 중 | 스켈레톤(짧게 보일 수 있음) |
| 결과 | 1권 이상 | 카드 목록 |
| 빈 결과 | 저장은 있으나 검색·필터 결과 0건 | "조건에 맞는 책이 없어요" + 조건 초기화 |
| 오류·캐시 표시 | 해당 없음 | 로컬 데이터만 쓰므로 네트워크 상태와 무관 |

### 3-3. 상세 (S3) — U-06, U-11, U-12

| 순서 | 구성 | 내용 |
|---|---|---|
| 1 | 상단 바 | 뒤로, 하트(즐겨찾기 토글) |
| 2 | 제목 | 가장 크게 |
| 3 | 정보 블록 | 왼쪽 큰 이미지, 오른쪽 저자 · 출판사 · 출간일 · ISBN · 정상가 · 할인가(없으면 줄 생략) |
| 4 | 책 소개 | 요약 + "…"(요약이 잘린 경우) + '전체 소개 보기'. 소개가 비면 "소개 정보가 없어요" |

| 상태 | 조건 | 표시 |
|---|---|---|
| 로딩 | key 로 조회 중 | 골격 |
| 정상 | 책 찾음 | 위 구성 |
| 오류 | key 에 해당하는 책 없음(드묾) | "책 정보를 찾을 수 없어요" + 뒤로 |

### 3-4. 창 크기별 배치

| 창 너비 | 배치 |
|---|---|
| 600dp 미만 | 한 칸. 카드 탭 → 상세로 좌우 슬라이드, 뒤로 → 목록 |
| 600dp 이상 (태블릿·펼친 폴더블·가로) | 목록 + 상세 2칸. 카드 탭은 이동이 아니라 오른쪽 칸 갱신. 선택 전에는 오른쪽 칸에 "책을 선택하세요" |
| 공통 | 하단 탭바 유지(추천). 접기·펼치기·회전 후 검색어·스크롤·선택한 책 유지 |

2칸 폭 비율은 구현 단계에서 정한다. 탭을 바꿔도 각 탭의 선택·스크롤은 따로 유지한다.

## 4. 네트워크 불안정 시나리오

| ID | 상황 | 사용자가 보는 것 |
|---|---|---|
| Q-01 | 요청이 3초를 넘기거나 연결이 없고 저장된 결과가 있다 | 캐시 결과 + 안내 줄(마지막 갱신 시각). 검색어·정렬 조합별 저장(최근 20개, 조합당 5페이지). 같은 검색의 저장 결과가 없으면 저장된 모든 책에서 찾은 결과 + "오프라인이라 저장된 책에서 찾았어요" |
| Q-02 | 같은 검색어를 처음 검색하는데 연결이 없다(캐시 없음) | 오류 화면 "인터넷 연결을 확인해 주세요" + 다시 시도. 즐겨찾기 탭은 그대로 동작 |
| Q-03 | API 키 오류(401·403) | 저장된 결과가 있으면 그것을 보여 주고 토스트로 "서비스 설정에 문제가 있어요". 없으면 같은 문구의 오류 화면(키·응답 원문 미노출). 재시도해도 같으므로 안내 위주 |
| Q-04 | 서버 오류(5xx·429·형식 오류) | "잠시 후 다시 시도해 주세요" + 다시 시도 버튼. 자동 재시도는 없다 |
| Q-05 | 2페이지 이후 로드 중 실패 | 이미 받은 목록 유지, 목록 끝에 "다시 시도". 5페이지를 넘긴 구간은 캐시가 없어 같은 방식 |

## 6. 고려했지만 구현하지 않은 것

| 항목 | 왜 고려했나 | 왜 하지 않나 |
|---|---|---|
| 최근 검색어 | 입력 부담 줄이기 | 작성자가 삭제. 원문 범위 밖 |
| 연결 상태 사전 감지 | 오프라인이면 즉시 캐시 | 데이터 계층이 Context 를 갖게 됨. 3초 타임아웃이 같은 효과를 낸다(v1 폐기 이유 3) |
| 자동 재시도·백오프 | 5xx 일시 오류 | 사용자가 다시 시도를 누르면 충분. 할당량 소모 위험 |
| 즐겨찾기 서버 동기화 | 기기 간 공유 | API 에 없음. 원문은 로컬 저장 |
| 책 소개 전문 | 요약 250자 잘림 | 스크래핑은 약관·구조 변경 위험. Custom Tab 으로 대체 |
| 검색 결과 캐시 만료 | 오래된 데이터 | 오프라인 가치가 더 큼 |
| 다크 모드·큰 글씨 대응 점검 | 접근성 | 시스템 설정 존중까지만. 별도 검증은 하지 않음 |
| 멀티 윈도우 창 크기 연속 조절 | 폴더블·태블릿 | 600dp 한 경계만 둔다. 세분화는 사용 데이터가 필요 |

## 7. 확인 필요

해소된 것: 앱 시작 시 마지막 검색 복원은 넣지 않고 오프라인 검색을 저장된 모든 책으로 넓힘(U-13) / 즐겨찾기 토글은 `ToggleFavoriteUseCase(book, isFavorite)` 하나 유지 / 금액 구간 확정(구간 목록은 화면, domain 은 `IntRange?`) / 다음 페이지도 `SearchBooksUseCase` 에 page 로 합침 / 책 정보는 검색 결과를 받을 때 저장 / Custom Tab 은 UseCase 없는 화면 동작.

1. **추천값 확인.** 디바운스 400ms, 안내 문구, 탭바 유지는 `추천안 기본 채택`이다. 바꿀 것이 있으면 알려 달라.
